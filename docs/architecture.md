# 架构

- `src/renderer`：Vue 3、Pinia、Element Plus 虚拟文件树及按需加载的 Monaco。只保存索引和当前预览，不接收整个 APK。任务事件集中呈现在底部。
- `src/preload`：只暴露固定方法的 `contextBridge`；拖放路径由 Electron [webUtils](https://www.electronjs.org/docs/latest/api/web-utils) 从本机 File 对象取得，不传给渲染进程。
- `src/main`：校验 IPC 来源和输入，按 SHA-256 管理项目，串行处理导入，按需限流读取预览，统一运行 SDK 工具。APK 内容不能直接调用文件系统或启动进程。
- `src/shared`：IPC 通道、参数、响应和任务事件的公共类型。

生产窗口启用 sandbox 和 context isolation，关闭 Node integration，禁止顶层页面导航和弹窗。渲染进程仅访问本地静态资源，预览文本不会当作 HTML 执行。开发服务器只监听回环地址。

导入以流式方式创建快照并计算 SHA-256，然后检查 ZIP 中央目录和本地头、文件路径、重复名称、重叠条目、压缩类型、展开大小和 CRC。基本 Android 二进制清单必须有效；存在 aapt2 时还会用它读取清单。当前阈值：APK 1 GiB、单条目 512 MiB、展开 4 GiB、60,000 个条目、单预览 2 MiB。大于 1 MiB 的条目还限压缩比。导入期间不会展开整个 ZIP 到磁盘，也不会执行其中代码。

工作区使用独立目录与 JSON 索引；新项目写入临时目录后再重命名。取消与失败会清理临时数据，启动时也会处理遗留临时目录。ZIP 索引和预览按原始条目名区分大小写。后续添加解压功能时，应根据目标文件系统的命名规则检查落盘冲突。SQLite 留待需要全文搜索、构建历史或多版本查询时引入。

本地工具由主进程以参数数组启动，设置超时、缓冲输出上限和取消信号。反编译同时只运行一个任务。macOS 和 Linux 的反编译子进程使用独立进程组，以便取消时终止其子进程。退出时等待当前任务和工具探测结束，有超时兜底。

JADX 和 Apktool 读取已导入的快照。工具在临时目录输出，JADX 配置和 Apktool 框架缓存也放在临时目录。主进程按实际文件类型和路径构建只读索引。成功后用目录重命名提交到 `decompiled-v1/<sha256>/<engine>/`，失败或取消清除临时输出。Apktool 缓存仅保留 Smali、解码资源和清单，Java 预览及导出只使用已索引的 Java 文件。文件预览按需读取，单次最多 2 MiB。外部引擎尚未纳入独立 OS 沙箱，缓存大小在工具完成后验证。


解码原件保持只读。编辑保存使用工作区的 `edits/`，按文件路径哈希主键写入独立记录。保存先写临时文件，再重命名。构建从 APK 快照解码出完整临时项目，将已保存的内容应用后进行编译、对齐和签名验证。密钥库密码由 apksigner 从本次进程的环境读取。最终 APK 写入用户选择的新文件，构建历史只记录路径、时间和证书指纹。

版本对比按压缩包内精确路径和解压内容 SHA-256 判定变更。权限来自 aapt2。SDK 结论来自规则命中，网络地址与 SO 字符串是静态结果，保有采样和条目上限。


启动时根据索引或清单预览的最后使用时间，清理 30 天以上的可重建缓存。已保存编辑、其 Apktool 解码基础、导入快照与构建产物均保留。

原生代码视图使用本地 Ghidra headless。主进程只读取已导入快照中选中的 `lib/<ABI>/*.so`，验证 ELF 魔数并在临时目录创建分析项目。索引及函数结果按 APK 哈希、SO 路径及 Ghidra 版本缓存，函数内容按需生成。局部失败时界面可保留反汇编并显示反编译错误。单 SO 输入上限为 64 MiB，索引上限为 20,000 个函数。大函数的指令和反编译文本分别设置上限。
